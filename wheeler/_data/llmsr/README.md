# wheeler/_data/llmsr/ -- what ships with the LLM-SR engine

Three trees, all read at runtime by `wheeler.integrations.llmsr.recipes`:

- `recipes/` -- spec TEMPLATES, one per scoring recipe. Each is filled against a
  real CSV header by `wheeler llmsr scaffold-spec --recipe <key>`. The tokens
  look like `%%EQ_ARGS%%`; a template naming a token the scaffolder does not
  supply is a hard error, never a spec with a `%%` left in it.
- `specs/` -- worked, ready-to-run specs for the problems the demo tables carry.
  These are what the `/wh:llmsr-discover` act means by "the matching bundled
  spec". List them with `wheeler llmsr specs`.
- `data/` -- small SYNTHETIC demo tables, plus `make_demo_data.py`, the script
  that produces them.

## Attribution

The method is **LLM-SR** (Shojaee et al., ICLR 2025, arXiv:2404.18400), which
builds on DeepMind's **FunSearch** (Romera-Paredes et al., Nature 2023). A paper
using a discovered equation cites those, not Wheeler. The BibTeX is in
`wheeler/integrations/llmsr/vendor/NOTICE.md`.

The specs here are **Wheeler-written starting points modelled on the LLM-SR
problem families**, not copies of upstream's specification files. Nothing in this
directory reproduces upstream's own spec text or their datasets.

## The demo data is synthetic, and says so

`bactgrow_demo.csv`, `bactgrow_strains_demo.csv` and `oscillator_demo.csv` are
generated by `make_demo_data.py` from laws written in that file, with a small
measurement error added. They are **not** the paper's data. They exist so a
scientist can run the whole loop end to end before pointing it at a recording
that matters, and so the answer a search is supposed to find is checked in beside
the question.

Regenerate them with:

```bash
python wheeler/_data/llmsr/data/make_demo_data.py
```

The generator uses no random number generator (an additive recurrence for the
sample positions, an integer LCG for the noise) and writes six decimals, so the
tables are reproducible across machines. `tests/integrations/llmsr/test_bundled.py`
reruns it and compares against what is checked in.

| table | columns | law | notes |
|---|---|---|---|
| `bactgrow_demo.csv` | `b,s,temp,pH,growth` | Monod uptake times a temperature optimum times a pH optimum | ungrouped |
| `bactgrow_strains_demo.csv` | `strain,b,s,temp,pH,growth` | the same law, three strains differing in gain and temperature optimum | pair with `--group-by strain` |
| `oscillator_demo.csv` | `t,x,v,a` | `a = -2.5x - 0.35v - 0.6x**3` | `t` is recorded but does not appear in the law |
