# Wheeler conversational memory: implementation audit

Inspected 2026-09-15 at commit `9965f0af13d1ae66fa92282e6ebd2e8845b30e0b`. Working tree was clean before this research. This report changes documentation only. No graph mutations or production tests were performed. A read-only `graph_context(topic="Wheeler memory")` returned empty. Findings below concern checked-out source, not an assertion about all installed hosts.

## The mission boundary

Wheeler's product is the provenance guarantee; the graph is infrastructure. Context management serves research, and the scientist owns judgment. A memory feature fits if it makes research decisions, corrections, and working preferences traceable and reusable. A general personality profiler or autonomous belief-forming agent is a different product. Sources: [mission](/Users/maxwellsdm/Documents/GitHub/wheeler/docs/mission.md:9), [context pillar](/Users/maxwellsdm/Documents/GitHub/wheeler/docs/mission.md:22), [north star](/Users/maxwellsdm/Documents/GitHub/wheeler/docs/mission.md:46).

## What exists in runtime

1. **Non-file observations are already first-class stored content.** `ResearchNoteModel` has `title`, `content`, and `context`. It does not require a file path. `add_note` can create an Execution and link its source entities in the same call. Every note goes through the shared graph/JSON/synthesis dispatch. Thus storage capacity is not the missing layer. Sources: [model](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/models.py:165), [MCP](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/mcp_mutations.py:258), [provenance helper](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/mutations.py:46), [dispatch](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/__init__.py:684).

2. **A remembered statement can already be linked to its research context.** The model includes session ID, timestamps, tags, origin fields, change log, and a scalar custom bag. `RELEVANT_TO`, `AROSE_FROM`, `CONTRADICTS`, `WAS_DERIVED_FROM`, and Execution provenance exist. There is no first-class Preference, Correction, Episode, or Memory type in the canonical type union, and no `SUPERSEDES` relationship. Sources: [base fields](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/models.py:20), [types](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/models.py:194), [relationships](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/graph/schema.py:75).

3. **Retrieval can find notes, but routine context does not apply them.** Keyword search includes notes and semantic/fulltext retrieval provides additional paths. `search_context` expands graph provenance. However, `graph_context` only loads Findings, OpenQuestions, and Hypotheses. Search summaries for ResearchNotes use the title only, not the operative content. These mechanisms do not select applicable active preferences by scope, resolve superseded instructions, or inject a bounded preference block. Sources: [keyword channel](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/search/retrieval.py:103), [note summary](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/search/retrieval.py:318), [expansion](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/search/retrieval.py:334), [context queries](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/graph/context.py:69).

4. **Field edits have an audit trail, not a correction lifecycle.** `update_node` validates fields, timestamps changes, and appends old/new values to the knowledge JSON's change log. This is useful machinery but does not encode why a conversational claim was wrong, who endorsed the replacement, when a preference applies, or which former instruction is now inactive. The MCP wrapper exposes fewer fields than the model: adding `custom` or typed memory fields internally alone does not make them callable through MCP. Sources: [update validation](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/mutations.py:1042), [change log](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/__init__.py:295), [MCP update surface](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/mcp_mutations.py:647).

5. **Source tracing is not conversation tracing.** `_SESSION_ID` is generated per MCP server process, not supplied as a stable host conversation/turn identifier. Request logs contain operation metadata, not the source utterance or a turn locator. A note's `context` is free prose. Therefore a note linked to an Execution proves the recording operation, not the exact user statement or the scientific correctness of the recorded statement. Sources: [session ID](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/mcp_shared.py:24), [request log schema](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/request_log.py:17).

## What is an act convention, not automatic behavior

- `/wh:pause` explicitly walks the conversation and captures endorsed results, decisions/rationales, and unresolved questions. It excludes casual chat, debugging detours, and abandoned tangents. This exclusion could lose a reusable debugging lesson unless a more targeted learning capture exists. [Pause sweep](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/commands/wh/pause.md:113).
- `/wh:close` asks the scientist for missing conversational artifacts before orphan grouping. A normal chat that never invokes close/pause has no equivalent capture guarantee. [Close sweep](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/commands/wh/close.md:112).
- `/wh:chat` suggests Findings, Hypotheses, and Questions with explicit approval, but does not offer a preference/correction category. These are prompt instructions, not an extraction engine. [Chat suggestions](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/commands/wh/chat.md:46).
- `/wh:note` creates a ResearchNote, writes `.notes/N-xxxx.md`, and indexes it. Its prose calls that file the real artifact, but `ResearchNoteModel` itself has no path/hash field tying it to that file. [Note act](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/commands/wh/note.md:39), [artifact wording](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/commands/wh/note.md:91).

## Hooks: distinguish project wiring from distributed plugin

The checked-out project's `.claude/settings.json` wires `Write|Edit` to `wheeler.hooks.auto_register` and `Read|Write` to file-access tracking. Auto-registration recognizes `.notes/`, `.plans/`, `docs/`, and `synthesis/` prose files, calls `ensure_artifact`, and logs failures without surfacing them. It captures files after they exist, not conversational statements. Sources: [project hooks](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/settings.json:3), [registration](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/hooks/auto_register.py:93), [path policy](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/hooks/auto_register.py:43).

The generated plugin's `hooks/hooks.json` only provides a SessionStart legacy-shadow warning. Do not infer that the project's file hooks run for every installed plugin or for Codex. Neither inspected hook configuration captures user turns or compaction. [Plugin hooks](/Users/maxwellsdm/Documents/GitHub/wheeler/hooks/hooks.json:1).

## Concrete continuity defect found

Pause stores `session-continuation:<PL-id>` in a note's **context**. Resume searches `query_notes(keyword="session-continuation")`. That query only filters **title/content**, not context. Following the prescribed writes literally can make the saved note invisible to the prescribed read unless the marker happens to occur in its text. This is a statically verified mismatch, not a reproduced live-Neo4j failure. Sources: [pause write](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/commands/wh/pause.md:136), [resume read](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/commands/wh/resume.md:27), [query predicate](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/queries.py:547).

## Proposed smallest extension

Use a deliberate memory-capture act and a typed ResearchNote extension first. Suggested optional fields: `memory_kind` (preference, correction, lesson, decision), `scope` (project/task/act), `status` (proposed, active, superseded, rejected), `source_document`, `source_locator`, `endorsed_by`, `valid_from`, `valid_until`, and `supersedes`. Keep explicit user instructions distinct from agent-inferred suggestions. Fields default absent/empty so existing notes retain their old behavior. A correction to a scientific result must still follow its scientific evidence and endorsement process; a preference is not a scientific Finding.

Why ResearchNote first: compatible existing JSON, rendering, note tooling, and type labels; no new canonical node migration. A new Memory label is reasonable later if separate indexes, permissions, lifecycle tools, and cross-project ownership prove necessary. It immediately expands the prefix/model registry, schema, renderers, retrieval, mutation/query servers, backups, and tests. A `custom` bag prototype is cheap, but not a final contract: it lacks typed validation and the current public MCP `add_note`/`update_node` wrappers do not expose it.

**Make the conversation source an artifact without circular provenance.** Save an immutable, minimal quoted episode under `.notes/episodes/<unique-id>.md`, with host/thread/turn locators when actually available; label any reconstruction as a summary. Register it with `ensure_artifact(artifact_type="document")` to obtain `W-source`. Then create `N-rule` with `execution_kind="memory-capture"`, `used_entities="W-source"`. The valid chain is `N-rule -> WAS_GENERATED_BY -> X-capture -> USED -> W-source`. The source snapshot must contain the earlier evidence, not merely a rendering of `N-rule`; do not have `X-capture` both generate and consume the same source. `.notes/*.md` maps to Document today, not ResearchNote, and unchanged `ensure_artifact` is path/hash-idempotent. Sources: [artifact mapping](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/mutations.py:546), [hash behavior](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/mutations.py:856).

Add a separate read-only `memory_context(scope, task)` path or a clearly separated section in `graph_context`. Return active applicable guidance, its status, exact content, and source IDs under a strict budget. Exclude superseded rules from guidance while preserving historical traceability. Connect a later Execution to the rule with `USED` only when it actually informed the action. Do not use graph tier promotion or embedding similarity as a substitute for user endorsement or correction validity.

## User clarification: procedures attached to the artifact being accessed

The primary target is more specific than preference recall: after a mistake querying database A, correct the harness when possible, attach any residual procedure to A, and discover that procedure before a different task accesses A. Discovery must follow resource identity even when the new question has no semantic resemblance to the original correction. The design above should therefore be read as capture/provenance groundwork, not as a recommendation to make conversational similarity the trigger.

### Identity that exists, and what a database still needs

Wheeler's node ID is stable once created, but its `ensure_artifact` resolver is explicitly **file-path keyed**. It hashes disk content and looks up portable, absolute, and legacy relative path spellings in the project namespace. `${ROOT}` paths help a known file survive machine changes; they do not identify a database service. Neither a hash nor a filename is the correct identity for "this research database across future queries." [Resolver](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/mutations.py:711).

`Dataset` can represent a local `.db` file today, but `add_dataset` and `ensure_artifact` require an existing filesystem path. A network database URI is normalized as a local path and fails that contract. `origin_database` identifies the Wheeler graph to which a node was written; it is just a configured database name, without endpoint identity, and must not be repurposed as the research resource's identity. [Path validation](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/tools/graph_tools/_field_specs.py:105), [origin stamp](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/machine.py:205).

Proposed small first slice: a registered resource manifest, e.g. `resources/retina-db.yaml`, is a Document artifact with a deliberately assigned stable `resource_id`, resource kind, logical instance/database/schema, and connection aliases that contain no credentials. The manifest represents an external database; its own file hash tracks changes to the manifest only. Later, first-class non-file Resource metadata may be cleaner than pretending the manifest's file path is the database. Identity resolution should map connection profiles and equivalent endpoints to the explicit resource ID; two databases named `neo4j` or `research` must remain distinct. Query text is an access operation on the resource, not its identity.

Store the procedure in a versioned Markdown Document and relate it to the resource via existing `RELEVANT_TO` initially. That relationship alone is insufficient for execution: an explicit procedure kind, active status, resource ID and operation selectors are still needed. A dedicated `APPLIES_TO` relation would make this semantic distinction clearer, but is not in today's whitelist. Source episode -> capture Execution -> procedure remains the provenance chain; procedure -> resource is the applicability link, not a claim that the resource was generated by the correction.

### Before-access delivery: feasible seam, absent guarantee

The existing `track_file_access` hook records resolved paths after Read/Write in a session text file. `read_before_mutate` checks that text file before a small group of Wheeler metadata mutations. It does not read procedures, does not intercept database queries, and explicitly allows node-ID-only operations whose path is unknown. The settings matcher targets bare `mcp__wheeler_mutations__...` names; it is not a universal interceptor for plugin-scoped tools. [Tracking](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/hooks/track_file_access.py:22), [allow gaps](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/hooks/read_before_mutate.py:45), [matcher](/Users/maxwellsdm/Documents/GitHub/wheeler/.claude/settings.json:25).

For Wheeler's own Cypher access, a deterministic resolver can run at the `run_cypher` tool boundary because the configured graph target is already known there. Today it accepts a query string and executes it without consulting attached procedures. For an external research database, put the same resolution call in its database adapter or query harness, which knows the connection profile before execution. Broad shell interception cannot reliably recover resource identity from arbitrary Python/SQL code. A read-only `resolve_resource_guidance(resource_id, operation)` tool is a useful common primitive, but prompting agents to call it voluntarily does not establish a before-access guarantee. [Cypher boundary](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/mcp_core.py:396).

Known mechanical fixes belong in the adapter and its tests: e.g. qualify the right schema, bind parameters correctly, reject unsupported commands. Residual judgment-bearing procedures should be delivered before the action. Returning a reminder after the SQL has executed is too late. An adapter can deterministically refuse the first action with the active procedure IDs/body until an explicit preflight has been satisfied; a host hook may instead inject them before execution where the host supports that. Either approach needs a real host-specific test. The current hooks establish neither delivery path, especially on Codex.

### A saved procedure is not automatically a registered host skill

Wheeler's act loader only reads the packaged `_data/commands` directory and caches the corpus for the process lifetime. `get_act` and generated host stubs expose those packaged acts; graph-linked Markdown is not scanned into that catalog. Therefore adding a local procedure file and graph edge does not make it discoverable as a native skill. [Act loading](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/acts.py:136), [cached corpus](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/acts.py:174), [generated stub](/Users/maxwellsdm/Documents/GitHub/wheeler/wheeler/build_plugin.py:280).

Prefer serving an attached procedure through the resource resolver initially. Exporting it as a native host `SKILL.md` can follow when useful, but host registration/reload must be tested separately from deterministic attachment lookup. An attached procedure does not require inventing a new orchestration engine or expanding the global skill catalog on every correction.

### Deterministic acceptance tests

1. Capture a lesson on database A; begin a fresh session with an unrelated task against A; assert the active procedure is delivered **before** the first query reaches the driver.
2. Access database B with the same topic and same database name on another instance; assert A's procedure is absent. Access A through an approved alias; assert it is present.
3. Change a schema/version applicability condition; assert incompatible procedures are withheld or flagged, and a superseded procedure cannot become active through search ranking.
4. Apply a harness fix and retain the original correction provenance; prove the invariant with an adapter test and remove redundant active instructions intentionally.
5. Exercise all supported host/tool paths, including plugin-scoped names and connection profiles. A raw shell bypass must be explicitly unsupported or separately instrumented, not silently claimed covered.
6. Verify failed/offline guidance resolution cannot be reported as a completed preflight; pick and test the project's fallback policy.

Existing test seams: [hook subprocess tests](/Users/maxwellsdm/Documents/GitHub/wheeler/tests/test_hooks.py:115), [track-then-mutate flow](/Users/maxwellsdm/Documents/GitHub/wheeler/tests/test_hooks.py:246), and `tests/test_ensure_artifact.py` / `tests/test_portable_paths.py` for alias and namespace behavior. These currently test file discipline, not artifact-triggered procedure discovery. This section is a design audit only; no runtime change or test run was performed.
