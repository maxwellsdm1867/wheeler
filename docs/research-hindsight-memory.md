## Recommendation

Borrow the boundary between **conversation evidence**, **derived memory**, and **explicit behavioral instructions**, plus the reliable host adapters that bring the right memory back into a later task. Implement those boundaries using Wheeler's existing files, graph and mutation path. Do not add Hindsight wholesale as a second authoritative memory database.

The user is identifying a real design opportunity: a corrected mistake or stated preference can become a small provenance-bearing artifact even if it never produced a paper, script, dataset, or figure. Wheeler's mission promises traceability and shared context while reserving scientific judgment for the scientist. This favors creating a narrowly scoped conversation excerpt and a memory derived from it. It does not favor silently turning an inferred preference into a scientific finding or an imperative. [Wheeler mission](/Users/maxwellsdm/Documents/GitHub/wheeler/docs/mission.md:7).

## What the source actually implements

### 1. Retain, consolidate, recall, reflect are separate stages

**Retain** processes source documents into chunks and extracted facts. The extraction model uses world/experience perspectives (intermediate extraction also uses assistant naming); these are not explicit preference/correction types. Document storage carries a content hash, optional original text, chunk text and metadata. Facts receive document and chunk IDs. This is meaningful textual lineage, but a source-linked extracted claim is not proof that the claim is true. **Consolidation** uses an LLM to propose create/update/delete operations on observations. It matches entity/facet, merges repeated evidence, updates state, and attempts to preserve important history. The prompts explicitly forbid arithmetic from incomplete evidence. Every accepted update must reference a supplied source fact and an observation retrieved for at least one of those facts. These are real validation constraints; correct synthesis remains model-dependent. [consolidation rules](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/consolidation/prompts.py:37) [action validation](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/consolidation/consolidator.py:2322)

**Recall** has semantic, keyword/BM25, graph and temporal result channels, reciprocal rank fusion, and per-channel caps that stop one expanding retriever from monopolizing a global budget. This is an incremental improvement opportunity for Wheeler's existing retrieval, not a reason to transplant the database. ### 2. Explicit directives have different authority from inferred observations

Directives are a separate table/API with name, content, priority, active status and tags. Reflect loads them and places them into its prompt as mandatory behavioral instructions. By contrast, observations are derived claims and mental models are generated documents. A field named `priority` is not a user-approval record; the create path shown does not require a provenance excerpt or scientist approval field. [directive creation](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/memory_engine.py:19709) [scoped directive loading](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/memory_engine.py:14686)

This is the most useful conceptual separation for Wheeler. "I prefer short summaries" explicitly stated by the scientist can be an active user preference, scoped to presentation. "The user seems to like short summaries" inferred from examples should remain a proposal or low-authority observation. "The fit was wrong because trials were pooled" is an operational lesson only once linked to its correction/evidence; a claim about the biology belongs in scientific evidence handling. Those three things must not acquire identical authority merely because all can be embedded and searched.

Do not copy Hindsight's blanket directive language. Its prompt says never violate directives even if other context suggests otherwise and follow them silently. Wheeler's injected memory should expose author, scope, status and evidence, remain subordinate to current user instructions, and avoid granting retrieved source text instruction authority. [directive authority language](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/reflect/prompts.py:72)

### 3. Corrections are artifacts, but supersession is partly heuristic

The current coding-agent integration gives an unusually direct answer to the user's proposal: after verifying remembered content is wrong, create a short document titled `Correction: <topic>` containing the old claim, corrected claim, and verified evidence. This is prompt instruction to the agent, not a guaranteed automatic correction detector or a typed correction transaction. The same injection tells the agent that recalled imperatives describe past decisions, not new tasks. [historical memory and correction instructions](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-integrations/coding-agents/src/core/inject.ts:59)

The conversation extraction mission asks for the fewest facts describing settled outcomes, preserves literal values and reference tokens, and keeps a rejected alternative inside one contextualized rejected fact. This avoids encoding every intermediate suggestion as a final decision. It is again a prompt-level policy, not a guarantee of correct final-state inference. [conversation extraction mission](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-integrations/coding-agents/src/core/missions.ts:31)

A generic reflection prompt resolves conflicting claims by latest `mentioned_at`; equal-date disagreements should be surfaced. That is reasonable for some changing user preferences, but unsuitable as Wheeler's universal scientific truth rule. A later speculation must not silently outrank a measured result. [latest-statement resolution](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/reflect/prompts.py:878)

### 4. Source retention, revision and retraction deserve more attention than extraction

Updates rewrite an observation's text and extend its source-memory IDs, recording a pre-update snapshot when observation history is enabled. History can be capped. Deletes actually delete the observation and its history. Thus Hindsight has useful history machinery but does not provide Wheeler's desired immutable derivation history by default. [history snapshots](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/consolidation/consolidator.py:2574) [observation rewrite](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/consolidation/consolidator.py:2639) [delete plus history deletion](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/consolidation/consolidator.py:2859)

The retraction module documents a consequential failure mode: deleting a source does not advance a "new content" watermark, so a derived document can keep repeating a claim whose evidence vanished. It compares stored `based_on` IDs against live IDs and carries the old text forward so a refresh can remove it. But if *all* evidence IDs are missing, it assumes unresolved/imported provenance, prunes dangling citations and retains prose. The code acknowledges this can leave truly retracted content stale. [source loss failure](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/reflect/retractions.py:1) [all-grounding-missing fallback](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/reflect/retractions.py:66)

For Wheeler, keep explicit source/revision identities and tombstones instead of losing source identity. A revised operational lesson should retain `old version -> replacement`, who authorized it, why, and the evidence. Retract or flag downstream guidance when its supporting artifact changes. Distinguish "old source was invalidated" from "reference cannot currently be resolved"; do not infer both from a missing database row. Existing scientific provenance propagation is an advantage to preserve here.

Consolidation also shows a concrete reliability lesson: apply the entire model-proposed batch atomically, including its "processed" marks. Its regression tests describe the old failure where a delete committed, replacement failed, source facts were marked complete, and the operation still reported success. The implementation now prepares expensive embedding work outside the write transaction and applies updates inside the caller's batch transaction. [atomicity regression contract](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/tests/test_consolidation_batch_atomicity.py:1) [transaction boundary](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/consolidation/consolidator.py:2646)

## Artifact-triggered procedural guidance: the sharper target

The user's clarified target is more specific than conversational memory: after correcting a query against database D, attach the reusable procedure to **that database artifact**, and activate it when D is accessed again, even for a semantically different task. Hindsight provides useful ingredients, but the inspected Claude/Codex integration does not implement this deterministic resource-access trigger.

The actual host registration is SessionStart, UserPromptSubmit and Stop, not a before-database-query callback. Recall/reflection starts from a prompt and repository bank. Directive tags filter instructions *after a caller invokes reflect with matching tags*; they do not themselves observe a database connection or map it to a stable artifact identity. A host or tool wrapper would still have to resolve that identity, select the relevant procedure, and inject or enforce it before access. [Actual host event registration](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-integrations/coding-agents/src/harness/hook-lifecycle.ts:220). [Directive selection on caller-supplied tags](/private/tmp/claude-501/-Users-maxwellsdm-Documents-GitHub-wheeler/e26d3ddc-83be-4673-bad2-87e382954104/scratchpad/memprov/hindsight/hindsight-api-slim/hindsight_api/engine/memory_engine.py:14686).

Therefore borrow **artifact-bound, source-linked guidance** and the shared-host-adapter architecture, not the assumption that semantic recall will always surface the relevant lesson. A canonical database artifact ID plus schema/version/environment constraints is a stronger key than a topical phrase like "SQL queries" or a hostname alone. If multiple tools can reach the resource, matching must live at a common supported access boundary or every adapter needs equivalent coverage. The current code inspection establishes no universal interception across arbitrary shell/SQL access.

First turn the correction into executable protection wherever possible: fix the query builder or connector, provide a tested view/helper, encode units/joins in schema or API contracts, or reject the known invalid operation. Preserve the correction's provenance, but do not use prose memory to compensate indefinitely for a fixable harness defect. For the residual context-dependent procedure, store an approved small artifact with applicability conditions, worked correct example, known failure, source evidence and revision. Resolve it by artifact identity before relevant tool use. This last design is a Wheeler proposal, not an implemented Hindsight guarantee.

## A Wheeler-sized design to prototype

This is a proposal, not a claim that Wheeler already implements these fields or acts.

1. A capture act creates a small local **conversation evidence artifact** with verbatim user/assistant excerpts, speaker roles, host/session/message IDs when available, capture time and content hash. Store what the scientist actually corrected, not an LLM reconstruction presented as a quote.
2. A **memory entry** points to that artifact and records `kind`, `scope`, `trigger`, `guidance`, `authority`, `status`, `source_ids`, and revision relationships. Distinguish user-stated preferences, verified operational lessons, and scientific corrections. Use existing Wheeler primitives if they can express the lifecycle cleanly; a dedicated type should follow an explicit domain-model decision.
3. Explicit user instructions can authorize capture immediately. Inferred preferences are proposals. Scientific interpretation/correction preserves the scientist checkpoint. A current instruction can override remembered preference without necessarily deleting it.
4. Retrieval selects a small active set by project/task/tool/domain scope, includes provenance links, and records which entries were supplied to the agent. General user preferences need an explicit cross-project policy; do not silently mix every project's lessons.
5. Revision marks an old entry superseded or disputed instead of destroying it, links the replacement and supporting correction, and uses the existing provenance/change-propagation path to flag dependent artifacts.

A concrete example: the scientist says "Do not pool trials when fitting this model; refit parameters per trial." Preserve that statement and the preceding mistaken fit as evidence. Derive scoped guidance for the relevant model/project. A future fitting act retrieves the guidance plus its origin. This is a memory artifact with useful operational effect, without turning a conversation preference into a scientific finding.

## Verification and maturity limits

This is substantial implemented software, not merely a README architecture. Evidence includes concrete store writes, typed consolidation actions, transport parsers, hooks, prompt builders, retraction mechanics and regression tests. It also carries considerable complexity that Wheeler does not need: a separate API/database service, worker lifecycle, multi-provider abstractions, scheduling, synthetic document refresh and host-specific installation.
